FreshStep, from plan to browser.

HTML + CSS + plain JavaScript. Browser-local progress. Node.js for development. GitHub Pages for sharing.

Read the complete canonical Markdown specification

How the pieces connect

GitHub PagesDelivers the app files from docs/. No application server.
→
The visitor's browserDisplays the page. JavaScript handles counting, activities, and daily check-ins.
↔
Browser storageRemembers the limit, date, count, and pending check-in on this browser.

Hosting sends files to the browser. Count changes move between JavaScript and localStorage; the saved count is not uploaded to GitHub.

During development, the local Node server delivers the same files at http://localhost:4173/. Local data and deployed-site data are separate.

Follow the journey through the files

1 · Setup → suggested limit

index.html provides the form; app.js handles input; domain.js calculates 75%, rounded up. Confirming writes the adjusted limit through storage.js.

Proof: 20 suggests 15, 10 suggests 8. Invalid inputs receive a clear message.

Implements PRD: Starting Limit.

2 · Plus/minus → circle and support

app.js checks the local day before applying the change. domain.js supplies the count and color; storage.js saves; the page updates.

Proof: limit 15 turns yellow at 10 and orange/red above 15. Limit 8 turns yellow at 6. Minus stops at zero; over-limit labels show the true count.

Implements PRD: Daily Counter and Circle.

3 · Activity choice → instructions and cartoon

activities.js holds a small curated collection. app.js opens the activity dialog with a summary, matching bundled SVG, and source link. Activities remain available before the support threshold.

Proof: closing an activity does not celebrate or alter the cigarette count.

Implements PRD: Craving Activities. Final exercise instructions must be researched during the build.

4 · “I did it” → encouragement

app.js opens the celebration; styles.css supplies brief confetti. Reduced-motion preferences disable the animation while retaining the message.

Proof: “Great work—you’re on your way!” appears. Cigarette count stays unchanged.

Implements PRD: Completion Celebration.

5 · Return or new day → restore/check in

storage.js restores a validated record. domain.js compares the device's local calendar date. Same day: retain the count. New day: reset to zero, retain the limit, and show the check-in.

Date checks also run before interactions and when a tab returns to focus, with a periodic check for a tab left open overnight. The pending check-in is saved until confirmed.

Proof: reload retains today's count; a new day offers the previous limit once the check-in is confirmed.

Implements PRD: Daily Check-In and States and Boundaries.

Where data lives

{
  "version": 1,
  "baselinePerDay": 20,
  "dailyLimit": 15,
  "dateKey": "2026-10-09",
  "count": 0,
  "checkInPending": false
}

One JSON record under freshstep:v1. Color and circle fill are calculated. Selected activities and confetti are temporary; no activity history or medical profile is stored.

If storage is blocked, keep the current session usable and explain that changes will not be saved. Invalid saved data leads to setup with an explanation.

Visual implementation

Light green and light yellow, readable gray system-font text, generous spacing, nature imagery, and original cartoon SVGs. Responsive single-column layout on smaller screens.

Keyboard-accessible controls and dialogs, visible focus, count announcements, and reduced-motion handling.

Keep it lightweight

No Python, Java, framework, database, account system, API key, external font, or confetti package.

Node v24.21.0 and npm.cmd v12.1.0 are available. No runtime npm dependencies are planned.

Run, verify, and deploy

Planned startup: node scripts/serve.mjs or npm.cmd start. Open http://localhost:4173/. Planned checks: node --test or npm.cmd test.

Node checks cover rounding, thresholds, corrections, invalid input, date rollover, and storage failures. Browser checks cover dialogs, persistence, responsive layout, and actual activity completion.

Deploy the public repository's /docs folder using GitHub Pages branch publishing. Use relative paths and check the live repository URL. Only app files are deployed; learner context remains outside the published folder and ignored by Git.

A short demo video and public repository remain required. Deployment is an additional learner goal.
